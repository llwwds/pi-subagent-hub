# pi-subagent-hub 2.0.0.0 平台化方案（已批准源码开发）

状态：已批准进入源码开发；首批 Skill 已导入独立开发目录，正式部署尚未执行。

## 目标

把现有 Pi 编排器扩展为多 Agent 载体平台。首批统一接入 Pi Agent CLI、Codex CLI 和 Claude Code CLI，平台负责自动发现/加载的 Skill 范围及 prompt 输入/输出，不修改载体内部。开放适配器契约，使其他具有可调用接口、可管理生命周期的开源或闭源 Agent 应用接入；平台不承诺无需适配即可运行任意第三方应用。

## 本版能力

| 模块 | 设计要求 |
| --- | --- |
| 多载体 | 适配器统一创建、消息、事件、状态、停止和故障报告；每个 subagent 保留独立 ID、执行实例或远程会话、事件与日志，本地载体另需进程隔离。创建时选择载体，未指定时使用 Pi。 |
| Web 看板 | 在现有面板上显示运行中数量及全部 subagent；可按载体和状态筛选。每个 subagent 展示 ID、名称、载体、模型、运行状态、启动时间、工作目录、获准 Skill 集、最近事件与错误，并提供状态时间线和详情。 |
| Skill 广场 | 将用户确认清单中的 Skill **复制**到平台私有存储，而非链接源目录或提交到公开源码仓库。每份副本记录稳定 ID、来源、版本/内容哈希和导入时间；更新产生新快照，不暗改已运行的 subagent。凭据、登录态和本地缓存不得随 Skill 复制。 |
| 创建时授权 | 新平台创建接口可指定 `all` 或 `only: [Skill ID...]`；未指定时默认可访问广场中当时已导入的全部 Skill。授权集在创建时固定，后续导入不会自动扩权正在运行的 subagent。 |
| 供应商切换 | 使用应用内独立的 CC Switch 副本管理各载体的 API、URL 和模型配置；与本机现有 CC Switch 及 Agent CLI 配置分离。Pi 的默认模型选择仍由 Pi 参数控制。 |

## 兼容与安全边界

- 现有 `/v1` HTTP 路由、CLI 指令、manifest v1、JSON 响应及其缺省行为保持不变；旧请求仍使用 Pi，已有 subagent 不因升级改变权限。新能力通过新增 API 路由和 CLI 指令提供。
- `only` 限制平台为该 subagent 配置的 Skill 自动发现和加载范围。它不限制载体通过文件或命令工具自行读取宿主文件，也不隔离凭据、网络或载体内置能力；看板和接口文档必须如实说明。
- 默认 `all` 意味着新创建的 subagent 可以使用广场里包括公司相关 Skill 在内的全部能力。该默认值仅适用于新增平台创建接口，须在审批时明确接受这一授权范围。

## 验收条件

1. 旧 CLI、HTTP 和 manifest 回归通过，运行中的 Pi subagent 不受开发或迁移影响。
2. Pi、Codex CLI 和 Claude Code CLI 均通过同一看板和新创建接口完成真实生命周期验证；载体暂不可用时给出明确原因。
3. 三个载体的自动 Skill 发现/加载仅包含该 subagent 获准的副本；默认 `all` 与快照更新行为有测试证据，并在界面明确标明没有操作系统级隔离。
4. 看板的运行中数量、状态、标识、详情和事件与实际进程一致。

## 已确认的输入

- 首批来源为预设 Skill 目录中的 49 份 Skill。副本保存在应用私有开发目录，不提交源码仓库。
- Codex CLI 与 Claude Code CLI 使用应用私有副本，不使用或修改本机现有安装与登录状态；不要求单独登录 Codex，而通过应用内 CC Switch 配置供应商。

开发只在源码仓库及应用私有开发目录进行，当前实现与未完成验收见 [`platform-api.md`](platform-api.md)；正式部署另行确认。
